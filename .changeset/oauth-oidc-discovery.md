Configure an inbound OAuth provider from its issuer. A provider with `issuer` set may leave out `authorizationUrl`, `tokenUrl`, `userInfoUrl` and `jwksUri`, and any it leaves out is read from the issuer's `/.well-known/openid-configuration` when the provider is used, cached for an hour. So a provider can be added with just an issuer, client id and client secret env. Endpoints the provider does configure are kept. The document's issuer must match the configured one, and the endpoints it names are held to the same policy as typed ones. The fetch follows the same rules as every other provider call (https and public addresses only in production, no redirects), with a 5 second timeout and a 64 KiB cap. The URL fetched is always the stored issuer's, never one taken from a request. `POST /system-config/oauth-providers/:id/discovery` reads the document again now, drops the provider's cached signing keys, and answers with the provider as sign-in will use it. A provider without an issuer still needs all three endpoints.

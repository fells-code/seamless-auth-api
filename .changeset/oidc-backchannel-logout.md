Send OpenID Back-Channel Logout 1.0 logout tokens when a first-party session behind a provider sign-in ends. When the provider service stores a provider session, the API records the `sid` each client got, for clients the session holds a grant for, under a model the provider service cannot read or delete. When the session ends, each client with a `backchannelLogoutUri` gets a `logout+jwt` token (`iss`, `aud`, `iat`, `exp`, `jti`, `sub`, `sid`, `events`) signed with the active provider key, posted with the same destination rules as inbound OAuth providers. `POST /oidc/sessions/:id/revoke` (RP-initiated logout) sends before it answers. `/logout` and `/logout/all` start a sweep straight away, and a 30 second sweep catches every other way a session ends (admin revoke, eviction, chain revocation, the sign-out-everywhere cutoff). Each client is told once per session, even across instances. New auth events `oidc_backchannel_logout_sent` and `oidc_backchannel_logout_failed`. Client metadata for the provider service now sets `backchannel_logout_session_required` whenever a back-channel URI is set, so ID tokens carry the `sid` the logout token names.
